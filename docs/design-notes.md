# 设计说明：设备状态判定与 USB 链路识别

本文说明界面上那两个小标签——**设备状态文字**与 **USB 链路速率徽标**——背后的判定逻辑，以及为适配不同 DPI 所做的布局处理。内容只讲思路与结论，不含实现代码。

---

## 1. 为什么需要重新设计状态判定

早期版本只用三条协议信号判断设备是否在线：`adb devices`、`fastboot devices`、9008 端口枚举。这套判定在冷启动与线材抖动时会给出错误结论：

| 现象 | 根因 |
| --- | --- |
| 刚开机明明连着，却显示"未检测到设备" | `adb devices` 超时过短，而首次调用需要拉起 adb server，冷启动耗时超过超时阈值 |
| 换线瞬间反复闪"未检测到设备" | `offline` 状态被当作"没有设备"处理 |
| 驱动正在加载时误报离线 | 判定只依赖协议响应，缺少"物理链路在线"这一层兜底 |

## 2. 新判定链路

判定按优先级自下而上收敛，先确定最强信号，再逐级降级：

```text
fastboot  →  EDL 9008  →  MTK BROM  →  ADB（系统 / REC / 未授权 / 离线）
        →  Windows 侧 USB 在线兜底  →  未检测到 / 暂不可用
```

关键改动：

1. **ADB 预热只做一次**：首次探测先启动 adb server，之后所有调用都是热调用。
2. **超时与重试分级**：对外部工具调用给足超时并重试一次；无设备时不做无效等待。
3. **`offline` 单列**：ADB 通道存在但设备未就绪，单独显示"设备：ADB离线"，不再混同于"未检测到"。
4. **USB 在线兜底**：协议面暂无响应、但系统中确实存在安卓厂商 USB 设备时，显示"设备：已连接"，模式确定后自动升级为具体模式。
5. **一轮只扫一次总线**：状态判定与 USB 徽标共用同一次总线扫描结果，不额外开线程。

## 3. USB 链路速率判定

链路的权威信号是 USB Hub 的端口连接信息，而不是描述符里的标称值。实现上按以下优先级取值：

```text
Hub 端口连接信息（Operating 位，权威）
  → 设备描述符 bcdUSB（≥ 0x0300 视为 3.x）
    → 端口 Speed 字节（仅用于区分 2.0 / 1.1）
```

两个高频误判被显式排除：

- **只有能力位不算数**：端口声明"支持 SuperSpeed"不等于"当前工作在 SuperSpeed"，必须看 Operating 位。
- **3.x 链路上 Speed 字节可能仍是 2**：此时应判为 SuperSpeed，而不是 2.0。

徽标与设备的匹配顺序为：**序列号精确匹配** → 唯一候选 → 匹配不上则不显示。宁可不出徽标，也不把别的设备的速率贴到当前设备上。

## 4. 布局：宽度不够时怎么退化

日志卡标题行同时要放"执行日志"、状态文字、USB 徽标与"保存日志"。窗口窄或 DPI 高时，硬挤必然重叠，因此做了三级退化：

| 级别 | 条件 | 表现 |
| --- | --- | --- |
| 1 | 完整文本放得下 | `USB 10G` / `USB3.2` / `USB2.0` / `USB1.1` |
| 2 | 放不下完整文本 | 紧凑文本：`10G` / `3.2` / `2.0` / `1.1` |
| 3 | 仍放不下 | 不显示徽标，宽度全部让给状态文字 |

状态文字同样有退化：先去掉 `设备：` 前缀保住模式名，再放不下用省略号截断，永不越界。

要点是**同一份几何计算同时驱动绘制、命中测试与光标判定**，避免"画在这里、点在那里"的错位；所有位置按实测字宽排布，DPI 变化等比缩放。

## 5. 可验证性

- 状态解析、速率分类、布局退化都是纯函数，可用固定输入离线断言，不依赖真机。
- 结构体字段偏移在编译期钉死，工具链换版本不会静默错位。
- 状态矩阵截图（见 [screenshots/device-state-matrix.png](../screenshots/device-state-matrix.png)）覆盖 96 / 144 DPI 与多档 USB 速率的组合，作为界面回归基线。
